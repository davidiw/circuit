# Pin-to-pin connection coverage

Generated by `npm run sweep` (the test suite fails if this file is stale). Every pin was connected to every other pin, one pair at a time, in two ways: **fresh**, where both pins are first taken off their nets and joined alone, which answers what the pair itself reveals; and **merge**, where the pins are joined as the app does it and their existing nets merge, which is what a user experiences.

**Basis.** Expectations come from the KiCad default ERC pin-type matrix (the industry list of which pin electrical types may share a net), plus domain rules for what that matrix cannot express: shorts to ground and motors that need a driver. **This is best effort, and honest about it.** *Covered* means every tested pair of that kind produced a violation or warning. *Allowed* means KiCad calls the pairing OK; a domain rule may still fire (voltage range, enable state, undriven net) and when it does it names one of the two pins, which the fresh column shows as fired (relevant). A firing that names neither pin would be noise and fails the test. *Gap* means KiCad calls it OK but a domain expert would still question it and no rule models it yet; the reason is in the last column. The coverage panel in the app lists evaluated dimensions for the same reason: a clean findings list only speaks for what was checked.
